# Ztt v0.6 专用函数与共享函数动态指令开销实验方案

## 目标和边界

在 `Polymorphic_Instructions_vs` 分支，以现有 AME_gem5 的 Ztt v0.6 比较运行时按类型分派到固定类型函数，和运行时选类型描述后进入共享函数体两种组织方式。重点统计准备、分派、初始化和矩阵搬运的架构动态指令数。

两方案底层均使用多态 Ztt 指令；结论仅涉及软件组织方式，不作为“多态 ISA 与显式类型 ISA”的比较。不修改模拟器编码、语义或时序模型，不以周期或吞吐作为主要结论。

## 工作负载与公平性

默认 `AMENLEN=4`、`AMEUDSZ=32`。一次调用对 `A[4][16]`、`B[16][4]`、`C[4][4]` 执行：清空累加器，重复 R 次 `C += A×B`，写回 C；有效 MAC 为 `256R`。

| kind | 类型 | 每轮 mmulacc.2d | 每轮输入加载 | 输出 |
|---:|---|---:|---:|---|
| 0 | FP32×FP32 | 4 | 8 | FP32 |
| 1 | INT32×INT32 | 4 | 8 | INT32 |
| 2 | INT8×INT8 | 1 | 2 | INT32 |

按同类型、相同任务成对比较，不从不同精度原始指令数推断方案优劣。输入由固定种子生成 `[-3,3]` 小整数，FP32 使用对应浮点表示。测量前按 `s=0…3` 打包：`A_s[i,q]=A[i,4s+q]`、`B_s[q,j]=B[4s+q,j]`。每个输入块占 64 字节；INT8 一块含四个子方阵，32 位类型四块各含一个子方阵。

同类型两方案使用完全相同的布局、地址、64 字节对齐和寄存器：`m0`、`m4` 输入，`acc0` 累加，`m8` 输出。每次重新建立类型状态；`asettyp` 已清空累加器，不重复清零，不跨调用缓存类型，不重排任务。预打包成本不计入，本实验测量预打包 GEMM 内核。

统一入口为：

```c
void run(const void *a, const void *b, void *c,
         unsigned kind, unsigned repeats);
```

类型编号运行时传入，类型描述构造、循环参数准备及分派全部计入；驱动在测量前确认 kind 合法且 `repeats>=1`。

## 实现和测量

手写汇编，禁用压缩指令及链接松弛。两方案按 FP32、INT32、INT8 顺序条件判断，不用查表或间接调用。专用版尾分派到三个固定类型函数，避免额外调用返回。共享版准备类型和块数后汇合到一份循环。

计算循环使用同一宏展开，专用三份、共享一份；不展开循环。每轮重新加载输入并恢复基地址；两方案寄存器分配、基址保存、恢复、寻址、循环控制完全一致。

测量区间：公共调用→类型分派→类型及其他准备→类型设置和初始化→加载/计算/循环→搬运/存储→内核返回。AME 获取/释放及状态检查、生成/打包/校验、日志与结果写出、测量标记及参数准备均排除。

实验目录独立配置与驱动复用 `example/common` bare-metal 启动和 `example/ame_config.py` 的 MinorCPU 平台，无需切换 `rvv1.0-ops`。局部配置仅增加批量 trace 开关，保留 CPU、内存和功能单元配置。

| 分类 | 内容 |
|---|---|
| 类型准备 | 类型常量构造及描述复制 |
| 其他准备 | 块数、循环计数初始化、基地址保存 |
| 类型设置与初始化 | 三次 msettyp、一次 asettyp；独立清零若有则另列 |
| 类型分派 | 条件判断、专用函数选择、共享路径汇合 |
| 有效计算 | mmulacc.2d |
| 矩阵数据搬运 | 输入加载、累加器搬运、输出存储 |
| 控制与寻址 | 分支、指针及计数更新、每轮基地址恢复 |
| 调用与返回 | 公共调用及内核返回 |
| 未分类 | 必须为零，否则失败 |

每条汇编指令由带大小的 ELF 标签标记类别，反汇编 PC 对应分类；`li` 展开为几条便计几条。标签、宏本身不计数，不按 `addi` 或笼统 Matrix 类推断语义。

使用 MinorCPU 提交路径的 Exec 轨迹，按标记 PC 切分区间。微操作以最后一个成员计一条架构指令，不能当作取指或微操作总数。区间同时读取 `instret`，逐次核对：

```text
分类之和 = 区间有效架构指令数
         = 提交计数差 − 逐 PC 识别的测量辅助指令数
```

辅助指令必须保存 PC、反汇编和次数；不得未经核验固定扣减。具体实现用两个 `rdinstret`，原始半开区间包含起始读、排除结束读；有效区间再排除起始读。包装函数保存现场与参数准备在区间外。

## 实验矩阵和指标

- `R=1,2,4,8,16,64,256`。
- 单类型三种序列各连续 96 次调用。
- 混合序列每类 32 次，按每组 1、4、16、32 个同类型任务，循环遍历三个类型。
- 同输入、同顺序，分别运行两方案，每个配置重复两次。
- 共 `7×7×2×2=196` 个配置，18,816 次调用。

每次都会设类型，切换频率仅用于观察顺序下分派路径，不解释为类型缓存收益。可以在四次独立仿真（方案×重复）内批量执行 49 个配置，但每个调用保留独立边界、结果和计数。

报告每调用总数和分类、类型设置/分派/搬运次数、指令/MAC、准备/计算指令比、搬运字节数。准备/计算定义为 `(类型准备+其他准备)/mmulacc.2d`。统一差值 `ΔN=N_shared−N_specialized`，正值为共享更多。静态机器码大小仅作辅助。

## 产物与验收

保留计划、汇编、驱动、配置、构建/运行/分析脚本、复现说明。构建及结果写入忽略跟踪的 `build/`。输出源码提交与文件快照、工具链版本和哈希、参数、模拟器和 ELF 哈希、反汇编、压缩原始提交轨迹、原始区间统计、正确性结果、CSV/JSON、分类型表格、随 R 开销曲线和解释实际汇编路径的 Markdown 报告。

1. 三类、全部 R、两方案的每个输出逐元素与宿主机参考相同。
2. AME 获取/几何/状态通过，无不支持类型或非法指令。
3. 每调用计算 `RB`、输入加载 `2RB`、输出存储 1 次，B=4/4/1。
4. 三次 msettyp、一次 asettyp；搬运与计算成对一致。
5. 分类、轨迹、instret 完整对账，未分类为零。
6. 反汇编确认专用三份、共享一份；循环机器码一致。
7. 重复运行计数相同，不一致须定位后才能生成成功报告。
8. 不预设共享更优；零差或共享增加少量跳转都如实报告。
